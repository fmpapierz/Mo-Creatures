====================================================================================================
  HOW IT ALL WORKS (read first)
====================================================================================================

* What the mod is
    DrZhark's Mo'Creatures ported from Minecraft 1.12.2/Forge (release 12.0.5) to Minecraft
    26.2. It adds 46 creatures, 182 items, 14 blocks, a custom Wyvern Lair dimension, natural
    spawning, and the core tame/breed/ride/capture interactions.

* Multi-loader design
    One shared 'common' codebase holds everything; thin 'fabric' and 'neoforge' entrypoints just
    call MoCreatures.init(). Cross-loader registration uses Architectury API 21.0.2.

* Why it builds for 26.x
    Minecraft 26.x ships UNOBFUSCATED, so no mappings are needed. The build uses the
    dev.architectury.loom-no-remap plugin; each platform's shadowJar bundles the common classes
    into the final jar (no remap step).

* Registration
    Architectury DeferredRegister/RegistrySupplier register entities, items, blocks, sounds,
    data components and the creative tab. In 26.2 every item/block/entity-type must carry its
    registry id at construction (.setId(...)), which the registry classes do explicitly.

* Rendering
    One generic renderer (MoCMobRenderer) draws all creatures via a render-state; each entity
    selects its own converted model + texture by sub-type. Renderers/model-layers are registered
    through Architectury's EntityRendererRegistry / EntityModelLayerRegistry, scheduled client-
    only via EnvExecutor.

* Entity state
    Base classes MoCAnimal/MoCMob/MoCAquatic/MoCFlyingInsect keep shared state (sub-type, tamed,
    adult, age, owner) on synched data, persisted with the 26.2 ValueInput/ValueOutput codec
    API.

* Spawning
    Spawn placements via Architectury SpawnPlacementsRegistry; overworld biome spawn entries via
    Architectury BiomeModifications (replacing NeoForge's loader-specific add_spawns JSON so it
    works on Fabric too).

* Dimension
    The Wyvern Lair is a data-driven datapack dimension (dimension_type + dimension + biome)
    bundled in the jar; the Staff of Portal item teleports the player between it and the
    Overworld.


====================================================================================================
  0. SETUP & HOW TO RUN
====================================================================================================
  How to launch the mod. The deliverable is ONE codebase that builds two jars (Fabric + NeoForge)
  for Minecraft 26.2. Everything below is identical on both loaders unless a row says otherwise.

  [ ] 0.1  Prerequisites   (INFO)
        Point : Know what the mod needs to run so loading doesn't silently fail.
        Do    : Have JDK 25 installed. In a real game instance you need: the mod jar + Architectury
                API 21.0.2; on Fabric also Fabric API 0.153.0+26.2 and Fabric Loader 0.19.3; on
                NeoForge 26.2.0.7-beta.
        Expect: Both jars are at: fabric/build/libs/mocreatures-fabric-26.2.0+26.2.jar and
                neoforge/build/libs/mocreatures-neoforge-26.2.0+26.2.jar.

  [ ] 0.2  Build both jars   (FULL)
        Point : Confirm the single codebase compiles and packages for both loaders.
        Do    : Open a terminal in the project root, set JAVA_HOME to a JDK 25, run:  ./gradlew
                build
        Expect: BUILD SUCCESSFUL; both jars (~20 MB each, 113 classes) appear under fabric/ and
                neoforge/ build/libs.

  [ ] 0.3  Run NeoForge dev client   (FULL)
        Point : Launch the game with the mod on NeoForge to test in-world.
        Do    : Run:  ./gradlew :neoforge:runClientDebug   (opens a Minecraft window)
        Expect: Window opens, reaches the main menu, then a test world. Log: 'initialized with 46
                creatures'.

  [ ] 0.4  Run Fabric dev client   (FULL)
        Point : Same, on Fabric — proves cross-loader parity.
        Do    : Run:  ./gradlew :fabric:runClientDebug
        Expect: Window opens and loads identically to NeoForge. Log: 'initialized with 46
                creatures'.

  [ ] 0.5  Run dev servers (optional)   (FULL)
        Point : Headless validation of registration / world / dimension.
        Do    : Run:  ./gradlew :neoforge:runServerDebug   then  ./gradlew :fabric:runServerDebug
                (one at a time; they share port 25565).
        Expect: Each boots to 'Done (...)!', registers mocreatures:wyvern_lair, no mod errors.

====================================================================================================
  5. TAMING
====================================================================================================
  Feed a creature its preferred food to tame it (sets you as owner, shows heart particles). NOTE:
  in this port only four species have a wired food; others spawn/behave but aren't tameable
  through feeding yet (a known simplification).

  [ ] 5.1  Tame a Bunny   (FULL)
        Point : Core taming loop, species 1.
        Do    : Hold a CARROT, right-click an untamed bunny.
        Expect: Carrot is consumed, 7 heart particles burst, bunny becomes tamed (you are owner).

  [ ] 5.2  Tame a Horse   (FULL)
        Point : Taming gate for the riding flow.
        Do    : Hold WHEAT, right-click an untamed horse.
        Expect: Wheat consumed, hearts, horse tamed.

  [ ] 5.3  Tame a Turtle   (FULL)
        Point : Species 3.
        Do    : Hold a MELON SLICE, right-click a turtle.
        Expect: Consumed, hearts, tamed.

  [ ] 5.4  Tame a Roach   (FULL)
        Point : Species 4 (rotten-flesh eater).
        Do    : Hold ROTTEN FLESH, right-click a roach.
        Expect: Consumed, hearts, tamed.

  [ ] 5.5  Owner is recorded   (FULL)
        Point : Taming stores your name for later (amulet/naming).
        Do    : After taming, capture+release with the amulet (section 9) or reload.
        Expect: Tamed flag and owner persist.

  [ ] 5.6  Other species not feed-tameable   (SIMPLIFIED)
        Point : Honesty: bigcat/ogre/etc. have no food wired.
        Do    : Try feeding a big cat etc.
        Expect: Nothing happens (expected). Use creative for those until per-species foods are
                added.
